## 1.所有者、所属组与文件权限

### 1.1 解读长格式输出

例如：

```text
-rwxrwxrwx. 1 xiaoming test 90 7月 26 06:32 1.txt
```

| 部分 | 含义 |
| --- | --- |
| 第一个字符 `-` | 普通文件类型 |
| `rwx rwx rwx` | 依次为所有者、所属组成员、其他用户的权限 |
| 权限后的 `.` | GNU ls 的额外访问控制标记之一，通常表示具有安全上下文而没有其他额外访问控制方法；不是第十个 rwx 权限位 |
| `1` | 硬链接计数；不是独立文件副本的数量 |
| `xiaoming`、`test` | 文件的所有者和所属组 |
| `90` | 此例普通文件的大小，单位字节 |
| 日期、`1.txt` | 默认显示修改时间及文件名 |

**所有者**是文件记录的拥有者，可由 `chown` 更改，不一定永远是创建者。**所属组**是文件自身记录的组，不等于所有者当前参加的全部组。

常见文件类型：

| 标记 | 类型 |
| --- | --- |
| `-` | 普通文件 |
| `d` | 目录 |
| `l` | 符号链接 |
| `b` | 块设备，例如磁盘设备 |
| `c` | 字符设备，例如终端、串口；并非“只能读取一次”的设备 |

### 1.2 文件和目录的 rwx

| 权限 | 普通文件 | 目录 |
| --- | --- | --- |
| `r`（4） | 读取内容 | 列出目录项名称 |
| `w`（2） | 修改内容 | 创建、删除或重命名目录项，通常还需目录的 x |
| `x`（1） | 允许执行，仍需格式及其他条件满足 | 搜索／穿越目录，按名称访问其中的对象 |
| `-`（0） | 没有该权限位 | 没有该权限位 |

删除文件主要取决于**父目录权限**，不能只看文件是否可写；sticky bit、ACL、只读挂载、SELinux 等还可能进一步约束操作。

传统模式位检查通常先匹配所有者，再匹配所属组，最后才匹配其他用户，不是把三组权限简单相加。实际访问还要考虑进程身份、附加组及额外访问控制。

### 1.3 chmod 修改权限

| 权限组合 | 数值计算 | 八进制数字 |
| --- | --- | --- |
| `rwx` | 4+2+1 | 7 |
| `r-x` | 4+0+1 | 5 |
| `r--` | 4+0+0 | 4 |
| `--x` | 0+0+1 | 1 |

以下为相互独立的教学示例，不必依次执行：

```bash
chmod 754 1.txt          # rwxr-xr--
chmod 111 1.txt          # --x--x--x
chmod u=rwx 1.txt        # 设置所有者权限，其他类别不由此项指定
chmod u=r,g=w,o=x 1.txt  # r---w---x
chmod u-x 1.txt          # 移除所有者执行权限
chmod a+r 1.txt          # 明确给所有类别增加读权限
```

- `u`：所有者；`g`：所属组；`o`：其他用户；`a`：以上所有类别。
- `+` 增加、`-` 移除、`=` 设置指定类别权限。
- `chmod +r 1.txt` 省略了类别，会受当前 **umask** 影响；不能无条件解释成“所有用户都获得读权限”。
- umask 还影响新对象的初始权限；没有默认 ACL 时，可理解为从程序请求的模式中屏蔽相应位，不是固定创建某一种权限。

### 1.4 修改所有者与所属组

```bash
# a 为现有用户，b 为现有组；修改所有者通常需管理员权限。
chown a:b 1.txt
chgrp b 1.txt

# 查看身份、组及结果。
id
groups
ls -l 1.txt
```

`chown` 管理所有者和组，`chgrp` 管理组，`chmod` 管理模式位。**权限严格划分有利于安全**，但不能仅凭一个数字模式判断全部访问条件。

## 2.用户与组管理

> 以下示例主要面向 shadow-utils 等常见实现；用户管理通常需要管理员权限，账户默认值依发行版配置而异。示例中的用户名、组名与目录需按实验环境准备。

### 2.1 创建、修改与删除用户

| 命令示例 | 含义与前提 |
| --- | --- |
| `useradd abc` | 创建账户；家目录及同名组是否创建取决于配置 |
| `useradd -m abc` | 明确要求创建家目录 |
| `useradd -d /home/sam sam` | 指定家目录路径，不保证创建该目录 |
| `useradd -m -d /data/ccc ccc` | 创建 ccc 并指定、创建家目录；上级路径需合适 |
| `useradd -m -g aaa sam` | 指定 sam 的主组为现有组 aaa，并创建家目录 |
| `usermod -d /home/xiaoming -g test sam` | 更改家目录字段及主组；不改用户名，也不自动搬迁原家目录 |
| `usermod -d /home/xiaoming -m sam` | 更改家目录并请求搬迁内容，需先处理登录会话及目标目录等条件 |
| `userdel sam` | 删除账户，通常保留家目录 |
| `userdel -r sam` | 同时请求删除家目录及邮件池，不保证清理其他位置所有归属文件 |
| `userdel -f sam` | 强制处理部分检查失败场景；账户仍在使用时可能留下不一致状态，不作为日常默认用法 |

这些命令展示不同操作情形，不应对同名账户不加判断地连续执行。不要让多个独立用户共用同一家目录。

`passwd` 通常修改自己的密码；管理员可按权限修改其他用户密码，例如 `passwd sam`。新密码是否接受，取决于所接入的认证和质量策略。

### 2.2 主组、附加组及组管理

- **主组**：账户记录中的主 GID；进程还可能具有不同的有效 GID。
- **附加组**：参与权限判断的其他组。
- **新文件所属组**：通常取创建进程的有效 GID；父目录设置 setgid 时通常继承父目录的组，文件系统及挂载选项也可能影响结果。不是“优先级最高的组”。
- **newgrp**：可在新 Shell 环境中切换当前组身份；不是给账户的多个组重新排优先级。退出该 Shell 后返回原环境。
- 组成员变更不会自动刷新所有已经运行的进程，通常需新登录会话等方式获得更新。

| 命令 | 用途 |
| --- | --- |
| `groupadd add` | 创建名为 add 的组 |
| `groupdel 组名` | 删除组；需处理主组引用等前提 |
| `groupmod -n 新组名 旧组名` | 修改组名 |
| `gpasswd -a abc xiaoming` | 将 abc 加入现有组 xiaoming 的成员列表 |
| `gpasswd -d abc xiaoming` | 从该组成员列表移除 abc，不等同于改变主组 |
| `usermod -aG test sam` | 向 sam 的附加组追加 test；省略 -a 的 -G 可能替换原附加组列表 |
| `newgrp test` | 切换当前组，能否切换取决于成员身份和认证条件 |

### 2.3 重要账户文件

> 用户管理工具通过系统接口和账户数据库工作，不能概括为“Bash 直接改这些文件”；远程目录服务的账户也不一定只保存在本地文件。

| 文件 | 主要内容 |
| --- | --- |
| `/etc/passwd` | 本地账户属性，通常含 7 个冒号分隔字段 |
| `/etc/shadow` | 口令验证字段与老化信息，普通用户不应可读；具体授权依系统而异，不一律只有 root 能读取 |
| `/etc/group` | 本地组及显式成员列表，用户的主组不一定在成员列表重复列出 |

`/etc/passwd` 字段：

```text
用户名:口令字段:UID:主GID:注释:家目录:登录Shell
root:x:0:0:root:/root:/bin/bash
```

`x` 通常表示口令信息另存于 shadow。UID／GID 是系统判断身份的重要标识，名称便于人阅读。

`/etc/shadow` 字段：

```text
用户名:口令验证字段:上次更改日:最小间隔:最大间隔:警告期:不活动期:账户失效日:保留字段
sam:<示意哈希>:20000:0:99999:7:::
```

上例的 `<示意哈希>` 是字段占位符，不能直接作为真实认证配置。日期字段通常以自 1970-01-01 起的天数记录。口令一般以加盐哈希等验证形式保存，不是可逆加密明文；具体格式由认证实现决定。

`/etc/group` 字段：

```text
组名:口令字段:GID:成员列表
test:x:1001:xiaoming,sam
```

bin、adm、sys 等是历史系统账户或组名称，各发行版的存在情况与职责不同。**系统账户不等于“假用户”**；能否交互登录，要结合登录 Shell、口令状态及认证策略判断。
