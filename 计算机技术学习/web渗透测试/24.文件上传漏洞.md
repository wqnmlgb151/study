> 文件上传漏洞是 Web 安全中**危害最高、最直接**的漏洞之一，攻击者通过利用该漏洞上传恶意脚本文件（如 WebShell、木马），从而直接**获取服务器控制权限（GetShell）**。

> ![upload靶场](assets/24.文件上传漏洞/file-20260803151340570.7z) 一次性全套配置

当文件上传时，若服务端脚本语言未对上传的文件进行严格验证和过滤，若恶意用户上传恶意的脚本文件时，就有可能控制整个网站甚至是服务器，这就是文件上传漏洞。

**风险处：**
1. 注册、修改个人信息处（如：上传头像等）
2. 敏感身份认证处（如：上传身份证图片/银行卡/个人图片等等）
3. 订单评价处（如：上传商品照片等)
4. 朋友圈/空间(如上传照片处)
5. 所有能上传文件的操作处


**文件上传漏洞利用前提：**
1. 能够将文件上传成功
2. 上传的文件可以解析和执行
3. 能够访问到上传的文件 路径

### 2. 黑名单过滤
- 系统内维护一个“禁止上传”的后缀名列表（如 `php`, `asp`, `jsp`, `exe`）。当上传文件的后缀名匹配到列表中时，则拒绝请求。 极易绕过
```PHP
<?php
// 获取上传文件信息（补全原代码缺失的变量定义）
$name     = $_FILES['file']['name'];
$type     = $_FILES['file']['type'];
$size     = $_FILES['file']['size'];
$tmp_name = $_FILES['file']['tmp_name'];
$error    = $_FILES['file']['error'];

// 打印信息（调试用）
echo $name.'<br>';
echo $type.'<br>';
echo $size.'<br>';
echo $tmp_name.'<br>';
echo $error.'<br>';

// 创建黑名单数组（修正错误的引号）
$black = array('php', 'asp', 'jsp', 'aspx');

// 截取上传文件的后缀名（使用 explode 并获取最后一段）
$fenge = explode('.', $name);
$exts  = end($fenge);

// 判断后缀是否在黑名单中
if (in_array($exts, $black)) {
    echo "非法后缀文件".$exts."请重试";
} else {
    // 移动文件到 upload/ 目录（修正字符串拼接语法）
    move_uploaded_file($tmp_name, "upload/" . $name);
    echo '文件上传成功';
}
?>
```

- 过滤的不全不严谨
	- `php php3 php4 php5 phtml`都会被解析为`php`
	- `JSP jspx jspf`都会被解析为`jsp`
	- `asp asa aspx`都会被解析为`asp`
	- `exe exee`都会被解析为`exe`
	- 大小写混写

- **fuzz模糊测试**
	- 在不知道过滤机制的情况下，通过字典等发起大量测试探索过滤机制
	- 标准定义：模糊测试（Fuzzing）是渗透测试中的一种自动化漏洞挖掘技术，主要通过向目标系统发送大量非预期、随机或半构造的数据，并监控程序是否崩溃、报错或产生异常行为来发现安全漏洞。

### 3. 白名单过滤
- 系统内维护一个“允许上传”的严格后缀名列表（如 `jpg`, `png`, `gif`, `pdf`）。只有文件扩展名完全匹配列表时才允许保存，其余一律拦截。  安全性高但不是绝对靠谱
```PHP
<?php
$name     = $_FILES['file']['name'];
$type     = $_FILES['file']['type'];
$size     = $_FILES['file']['size'];
$tmp_name = $_FILES['file']['tmp_name'];
$error    = $_FILES['file']['error'];

// 打印信息（调试用）
echo $name.'<br>';
echo $type.'<br>';
echo $size.'<br>';
echo $tmp_name.'<br>';
echo $error.'<br>';

// 将黑名单数组改为白名单数组（仅允许常见图片后缀）
$allowed = array('jpg', 'jpeg', 'png', 'gif', 'bmp');

// 截取上传文件的后缀名
$fenge = explode('.', $name);
$exts  = end($fenge);

// 改为白名单判断：后缀是否在白名单中
if (in_array($exts, $allowed)) {
    // 移动文件到 upload/ 目录
    move_uploaded_file($tmp_name, "upload/" . $name);
    echo '文件上传成功';
} else {
    echo "不允许的文件后缀：" . $exts . "，只允许 " . implode(', ', $allowed);
}
?>
```

- 组件漏洞绕过
- 操作系统的特性
- 代码逻辑问媒体绕过

## 四.利用windows特性绕过

### 点空格绕过
> Windows点和空格绕过是指在文件上传时利用Windows系统自动去除文件名末尾点(`.`)和空格( )的特性，突破后端黑名单限制。核心原理是后端黑名单未过滤特殊符号，导致传入的`test.php.`或`test.php` 通过校验，在Windows服务器保存时被自动截断还原为有效脚本文件。

windows自动去除了，但是上传时空格和`.`通过BP抓包加上，绕过后成功上传后，windows服务器会自动去除，进而达到上传木马的效果

---

### 文件流绕过
> 在 Windows 环境下，NTFS 文件系统支持在同一个文件名下宿主多个数据流。文件默认的内容存储在未命名的数据流中。如果我们在文件名后附带 **`::$DATA`** 标记，系统会明确将其识别为主数据流。

- 目标服务器必须是windows，linux服务器无法解析这样传上来的文件，会有个奇怪的后缀

- 可以将其他文件寄宿在其他文件身上，在资源管理器上面只能看见被寄宿的文件

 ```cmd
 echo 123 > 1.txt #将123写入1.txt文件
 echo 123 》 2.txt:3txt#将123写入3.txt，3.txt寄生到了2.txt，资源管理器只能看见2.txt
 
 notepad 2.txt:3.txt#使用记事本打开查看3.txt
 
 dir#使用dir进行查看会看见寄生文件有个奇怪的后缀
 
 
 ```

当后端代码采用**黑名单机制**（例如禁止上传 `.php` 后缀）进行校验，但在过滤时**没有清除 `::$DATA` 字符**时，就会产生漏洞。
- 攻击者上传 `shell.php::$DATA`，后端提取后缀名，由于匹配不到 `.php`，文件顺利通过黑名单拦截。

- Windows 系统在底层写入该文件时，会自动剥离并忽略末尾的 `::$DATA` 标记，将流内容写入主文件。

- 最终在服务器上落地并保存的文件名实际为 **`shell.php`**，从而成功实现恶意脚本绕过。

### Apache HTTPD 多后缀解析漏洞
> [指南](https://github.com/vulhub/vulhub/tree/master/httpd/apache_parsing_vulnerability/README.zh-cn.md)

服务器会从左到右处理多个后缀，如果任何后缀被配置为由特定处理器（如 PHP）处理，那么无论该后缀在文件名中的位置如何，都会被执行。这意味着一个名为 `malicious.php.jpg` 的文件仍然会被作为 PHP 代码执行，从而可能绕过仅检查最后一个后缀的上传限制。
