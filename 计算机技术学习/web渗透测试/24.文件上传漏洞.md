> 文件上传漏洞是 Web 安全中**危害最高、最直接**的漏洞之一，攻击者通过利用该漏洞上传恶意脚本文件（如 WebShell、木马），从而直接**获取服务器控制权限（GetShell）**。

> ![upload靶场](assets/24.文件上传漏洞/file-20260803151340570.7z)

当文件上传时，若服务端脚本语言未对上传的文件进行严格验证和过滤，若恶意用户上传恶意的脚本文件时，就有可能控制整个网站甚至是服务器，这就是文件上传漏洞。

**风险处：**
1. 注册、修改个人信息处（如：上传头像等）
2. 敏感身份认证处（如：上传身份证图片/银行卡/个人图片等等）
3. 订单评价处（如：上传商品照片等)
4. 朋友圈/空间(如上传照片处)
5. 所有能上传文件的操作处


**文件上传漏洞利用前提：**
1. 能够将文件上传成功
2. 上传的文件可以解析和执行
3. 能够访问到上传的文件 路径

## 一.文件上传过滤机制（后端发力）：

有关文件上传的PHP函数：
```PHP
$_FILES["表单值"]["name"];//获取文件上传的原始名称
$_FILES["表单值"]["type"];//获取文件的MIME类型
$_FILES["表单值"]["size"];//获取文件的字节单位大小
$_FILES["表单值"]["tmp_name"];//获取文件的临时副本文件名 临时路径

```

### 2. 黑名单过滤
- 系统内维护一个“禁止上传”的后缀名列表（如 `php`, `asp`, `jsp`, `exe`）。当上传文件的后缀名匹配到列表中时，则拒绝请求。 极易绕过
```PHP
<?php
// 获取上传文件信息（补全原代码缺失的变量定义）
$name     = $_FILES['file']['name'];
$type     = $_FILES['file']['type'];
$size     = $_FILES['file']['size'];
$tmp_name = $_FILES['file']['tmp_name'];
$error    = $_FILES['file']['error'];

// 打印信息（调试用）
echo $name.'<br>';
echo $type.'<br>';
echo $size.'<br>';
echo $tmp_name.'<br>';
echo $error.'<br>';

// 创建黑名单数组（修正错误的引号）
$black = array('php', 'asp', 'jsp', 'aspx');

// 截取上传文件的后缀名（使用 explode 并获取最后一段）
$fenge = explode('.', $name);
$exts  = end($fenge);

// 判断后缀是否在黑名单中
if (in_array($exts, $black)) {
    echo "非法后缀文件".$exts."请重试";
} else {
    // 移动文件到 upload/ 目录（修正字符串拼接语法）
    move_uploaded_file($tmp_name, "upload/" . $name);
    echo '文件上传成功';
}
?>
```

- 过滤的不全不严谨
	- `php php3 php4 php5 phtml`都会被解析为`php`
	- `JSP jspx jspf`都会被解析为`jsp`
	- `asp asa aspx`都会被解析为`asp`
	- `exe exee`都会被解析为`exe`
	- 大小写混写

- **fuzz模糊测试**
	- 在不知道过滤机制的情况下，通过字典等发起大量测试探索过滤机制
	- 标准定义：模糊测试（Fuzzing）是渗透测试中的一种自动化漏洞挖掘技术，主要通过向目标系统发送大量非预期、随机或半构造的数据，并监控程序是否崩溃、报错或产生异常行为来发现安全漏洞。

### 3. 白名单过滤
- 系统内维护一个“允许上传”的严格后缀名列表（如 `jpg`, `png`, `gif`, `pdf`）。只有文件扩展名完全匹配列表时才允许保存，其余一律拦截。  安全性高但不是绝对靠谱
```PHP
<?php
$name     = $_FILES['file']['name'];
$type     = $_FILES['file']['type'];
$size     = $_FILES['file']['size'];
$tmp_name = $_FILES['file']['tmp_name'];
$error    = $_FILES['file']['error'];

// 打印信息（调试用）
echo $name.'<br>';
echo $type.'<br>';
echo $size.'<br>';
echo $tmp_name.'<br>';
echo $error.'<br>';

// 将黑名单数组改为白名单数组（仅允许常见图片后缀）
$allowed = array('jpg', 'jpeg', 'png', 'gif', 'bmp');

// 截取上传文件的后缀名
$fenge = explode('.', $name);
$exts  = end($fenge);

// 改为白名单判断：后缀是否在白名单中
if (in_array($exts, $allowed)) {
    // 移动文件到 upload/ 目录
    move_uploaded_file($tmp_name, "upload/" . $name);
    echo '文件上传成功';
} else {
    echo "不允许的文件后缀：" . $exts . "，只允许 " . implode(', ', $allowed);
}
?>
```

- 组件漏洞绕过
- 操作系统的特性
- 代码逻辑问媒体绕过

### 4. MIME-Type（媒体类型）过滤
> MIME(ultipurpose Internet Mail Extensions)多用途网络邮件扩展类型，可被称为Media type或Content type，它设定某种类型的文件当被浏览器打开的时候需要用什么样的应用程序，多用于HTTP通信和设定文档类型例如HTML。之所以叫多用途网络邮件扩展类型，因为它最早被用于电子邮件系统，后用于浏览器。


- 客户端（浏览器）在发送文件时，会在 HTTP 请求头中的 `Content-Type` 字段里声明该文件的媒体类型（例如图片为 `image/jpeg`，文本为 `text/plain`）。服务器校验此字段是否合法。  形同虚设，BP抓包直接改

### 5. 文件头（Magic Number）过滤
- 服务器通过读取文件二进制数据的特殊前缀（魔术字）来判断文件真实类型（如 JPEG 为 `FF D8 FF`，PNG 为 `89 50 4E 47`）。  防君子不防小人，只验证了开头，可以拼接

### 6. 文件内容恶意代码过滤
- 服务器调用杀毒软件 API（如 ClamAV）或通过正则表达式/关键字匹配，扫描文件内容中是否包含恶意的敏感脚本函数（如 `eval()`, `system()` 等）。 存在滞后性，免杀对抗
### 7. 图像二次渲染过滤
- 服务器调用图像处理库（如 GD 库、ImageMagick）对上传的图片进行缩放、裁剪或格式重写，将原本的图片像素数据打碎并重新生成一张新图片。  期待渲染库出问题，做出针对的渲染木马

## 二.前端检测
> **在文件被发送到服务器之前**，浏览器通过 HTML 属性和 JavaScript 对用户选中的文件进行初步校验。

- 禁用`JavaScript`：在浏览器设置中关闭JS，验证代码不执行  BP中也能够进行删除JS
- 修改`HTML`属性：使用开发者工具（F12）删除`accept`或修改表单提交前的验证
- 直接构造`HTTP`请求：使用BP等工具绕过前端直接放服务器发起请求
- 修改文件信息（使用后端绕过的手段）

## 三.htaccess配置文件绕过
>`.htaccess`是一个纯文本文件，它里面存放着Apache服务器配置相关的指令。  
`.htaccess`主要的作用有：URL重写、自定义错误页面、MIME类型配置以及访问权限控制等。主要体现在伪静态的应用、图片防盗链、自定义404错误页面、阻止/允许特定IP/IP段、目录浏览与主页、禁止访问指定文件类型、文件密码保护等。  
`.htaccess`的用途范围主要针对当前目录。

```
AddType application/x-httpd-php
```
