> 文件上传漏洞是 Web 安全中**危害最高、最直接**的漏洞之一，攻击者通过利用该漏洞上传恶意脚本文件（如 WebShell、木马），从而直接**获取服务器控制权限（GetShell）**。

当文件上传时，若服务端脚本语言未对上传的文件进行严格验证和过滤，若恶意用户上传恶意的脚本文件时，就有可能控制整个网站甚至是服务器，这就是文件上传漏洞。

风险处：
1. 注册、修改个人信息处（如：上传头像等）
2. 敏感身份认证处（如：上传身份证图片/银行卡/个人图片等等）
3. 订单评价处（如：上传商品照片等)
4. 朋友圈/空间(如上传照片处)
5. 所有能上传文件的操作处


文件上传漏洞利用前提：
1. 能够将文件上传成功
2. 上传的文件可以解析和执行
3. 能够访问到上传的文件 路径

文件上传过滤机制：
1. 无过滤
2. 黑名单过滤
	- 系统内维护一个“禁止上传”的后缀名列表（如 `php`, `asp`, `jsp`, `exe`）。当上传文件的后缀名匹配到列表中时，则拒绝请求。极易绕过
3. 白名单过滤
	- 系统内维护一个“允许上传”的严格后缀名列表（如 `jpg`, `png`, `gif`, `pdf`）。只有文件扩展名完全匹配列表时才允许保存，其余一律拦截。  安全性高但不是绝对靠谱
4. MIME-Type（媒体类型）过滤
	- - 客户端（浏览器）在发送文件时，会在 HTTP 请求头中的 `Content-Type` 字段里声明该文件的媒体类型（例如图片为 `image/jpeg`，文本为 `text/plain`）。服务器校验此字段是否合法。  形同虚设，BP抓包直接改
